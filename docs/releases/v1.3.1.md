## 🚨 What's New in v1.3.1 — update now to restore sign-in

* **🔓 Sign-in works again after the portal's new security check** — iulms.edu.pk now puts a Cloudflare browser check in front of its login page, and v1.3.0 cannot get past it. Install v1.3.1 to sign in again and load live schedule, attendance, results, transcript, and voucher data straight away.
* **✅ Verification that explains itself** — When the portal needs a browser check, a redesigned Material 3 sheet shows the portal's own page in a rounded card, says plainly what is happening, and closes by itself the moment verification finishes. If the check needs a tap, the same sheet asks for it, with a clear Cancel and an explicit Continue.
* **👆 One tap, one tab** — The bottom bar now answers the first tap everywhere on every tab, including the edge of the selected pill and rapid switching between Schedule, Attendance, Result, Transcript, and Vouchers.
* **🏷️ A trust chip that fits** — The sign-in chip now reads "Direct HTTPS to iulms.edu.pk" and stays on one clean line on narrow phones and at large font sizes.
* **⏱️ No repeated checks** — Once the portal's check passes, the clearance is kept for the session and survives normal relaunches, so opening the app again does not restart verification from scratch.

## Fixes & Improvements

* **Nothing to reinstall or reconfigure** — v1.3.1 is signed with the same certificate as every earlier release, so it updates over v1.3.0 in place and keeps your saved settings.
* **A verification check is not a password error** — A portal security check is reported as its own state, never as "check your registration number and password".
* **Clean sign-out** — Signing out clears the session and the portal's verification state on this phone; remembered credentials are handled exactly as before.
* **The challenge page stays on the portal** — The verification page cannot navigate off iulms.edu.pk, so credentials never leave the portal's own origin.

## Under the Hood

* **One identity for every request** — OkHttp and the verification WebView send the same User-Agent, because the portal's clearance cookie is bound to it; a mismatched agent would silently invalidate a solved check.
* **Fast, quiet solving first** — A short off-screen WebView attempt clears non-interactive checks without UI; if the portal is waiting for a human tap, the sheet opens immediately instead of making the student wait.
* **One attempt at a time** — A single-flight gate serializes verification and sign-in across screens, so two tabs hitting the check together cannot start parallel dialogs or reset each other's session.
* **223 unit tests across 24 suites** — New challenge-detection, cookie-bridge, session-pair, and single-flight tests run alongside the existing suite; all pass before release.

## Data Ethics Statement

* **Direct to the portal.** Sign-in and every data request go over HTTPS to https://iulms.edu.pk. There is no MyIULMS server or database in the path.
* **Nothing collected in the background.** The app has no analytics, telemetry, or tracking, and does not upload portal data anywhere.
* **Credentials on your terms.** Remember me is opt-in; when enabled, credentials are encrypted on-device with an Android Keystore-backed key, and when disabled nothing is saved. Session cookies stay in memory, and signing out clears the session.
* **Unofficial and independent.** MyIULMS is not affiliated with Iqra University, and the academic data shown is the portal's own.
